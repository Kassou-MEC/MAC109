02 · The one big idea of the week

A class is a blueprint. An object is one real thing built from it.

You already use classes without knowing it. Window is a class; your MainWindow is one object built from it. TextBox is a class; txtName is one object. Today you write a class of your own.

→
new

The class (one file, written once)

Student is a new type, just like int or TextBox. Inside it you list the facts every student has. Each fact is a property: public string Name { get; set; }. get; set; means "you can read it and you can change it."

The object (as many as you want)

Student s = new Student(); builds one. Then the dot reaches inside: s.Name = txtName.Text;. Sound familiar? Title = "..." was the same move: a property, a dot, a value.

The list (a shelf for objects)

List<Student> students is a shelf that only accepts students. .Add(s) puts one on the shelf, .Count tells you how many, .RemoveAt(2) takes the third one off. The <Student> part is the sign on the shelf.

Two lists that must stay in sync. students is the data (your objects, invisible). lstStudents is the ListBox (text rows the user sees). Every time you add to one, add to the other. Every time you remove from one, remove from the other. Forgetting this is the #1 bug of Week 4.

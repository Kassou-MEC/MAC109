Meet the cockpit

🛩️— ▢ ✕

Your project is open. Four areas of VS Code do almost everything this semester — find each one before touching anything:

  • MainWindow.cs 💙 — your window: interface and logic, one C# file. You'll live here for weeks.
  • Program.cs — the ignition: starts the app, shows MainWindow. Look, don't touch.
  • MyStudioApp.csproj — the recipe card: which .NET, which packages — including Avalonia itself.
  • README.md — your repo's front page. You'll edit it in Level 10.
Where's the design file? Where's the drag-and-drop?
There isn't one — on purpose. In this course, the UI is C# objects: every button is new-ed, every setting is a property, every click is an event subscription. One file, one language, nothing hidden. When Week 5's classes-and-objects lecture arrives, it will be naming things you've already done for a month.

Press ▶ — your first run

🎬— ▢ ✕
  1. Open MainWindow.cs from the Explorer.
  2. Press F5 — or menu Run ▸ Start Debugging. If VS Code asks what kind of project, pick C#.
  3. First run only: the status bar says Restoring… — that's Avalonia downloading itself into the project (one time), then Building…
  4. …and a real window appears. Move it. Resize it. Maximize it. Close it with ✕ (that also stops the run).
✅ Checkpoint: a window opened, and you typed zero code. Resizing, minimizing, the ✕ button — all inherited free from Avalonia's Window class (that's the : Window on line 1 of your file). Ten seconds of celebration, then onward.
What did F5 actually do?
The whole Week 1 pipeline, for real: the compiler read your entire project and checked its grammar, translated it to universal IL, the .NET runtime JIT-translated that for this exact CPU, and the machine ran it. The same IL runs on Windows, macOS, and Linux — which is why your app is cross-platform without you doing anything.

Build the Greeter 💬

🗣️— ▢ ✕

The heart of Milestone 1: a button that answers. You'll add two fields, a Button, one +=, and a handler — turning the shell into the full program from the lecture's First Code tab:

MainWindow.cs — the complete Greeter (your target)
using Avalonia;
using Avalonia.Controls;
using Avalonia.Interactivity;
using Avalonia.Media;

namespace MyStudioApp;

public class MainWindow : Window
{
    TextBox txtName = new TextBox { Watermark = "Type your name…" };
    TextBlock lblGreeting = new TextBlock { FontSize = 18 };

    public MainWindow()
    {
        Title = "My Studio App — Maria";
        Width = 500; Height = 350;

        var lblWelcome = new TextBlock { Text = "Welcome to MAC 109!", FontSize = 22 };
        var btnGreet = new Button { Content = "Say Hello" };
        btnGreet.Click += BtnGreet_Click;

        Content = new StackPanel
        {
            Margin = new Thickness(20), Spacing = 12,
            Children = { lblWelcome, txtName, btnGreet, lblGreeting }
        };
    }

    void BtnGreet_Click(object sender, RoutedEventArgs e)
    {
        lblGreeting.Text = "Hello, " + txtName.Text + "!";
    }
}
  1. Type (don't paste) the two field lines above the constructor — feel IntelliSense appear after every new and every dot.
  2. Add btnGreet and the Click += line inside the constructor.
  3. Grow the Children list to all four controls, in top-to-bottom order.
  4. Add the BtnGreet_Click method after the constructor.
  5. F5 ▸ type your name ▸ click Say Hello.
The three ideas hiding in this file
(1) Fields vs var: txtName and lblGreeting live at class level so the handler can reach them later; lblWelcome and btnGreet are var locals nobody needs after setup. (2) The += subscription: "when this button is clicked, run that method" — your program now waits for the user. That's event-driven programming, and it's the single most important line in GUI code. (3) Read → glue → write: read txtName.Text, glue with +, write lblGreeting.Text. That rhythm is 90% of what GUI code does.
🏅 DELIVERABLE — Milestone 1 core, DONE! A window ✓ four controls built as C# objects ✓ a wired Click event ✓ personalized output on the window ✓. Show a neighbor — first-GUI energy is contagious.
8

Add a Clear button

✨— ▢ ✕

Real apps reset. Add a second button with its own event — proof that every control carries its own personality:

MainWindow.cs — three additions
// 1 · in the constructor, next to btnGreet:
var btnClear = new Button { Content = "Clear" };
btnClear.Click += BtnClear_Click;

// 2 · grow the Children list:
Children = { lblWelcome, txtName, btnGreet, btnClear, lblGreeting }

// 3 · after BtnGreet_Click, its sibling:
void BtnClear_Click(object sender, RoutedEventArgs e)
{
    txtName.Text = "";        // empty the box
    lblGreeting.Text = "";    // hide the greeting
    txtName.Focus();          // cursor back home, ready for the next name
}

F5. Greet ▸ the label lights up. Clear ▸ everything resets and the cursor jumps home. Two buttons, two subscriptions, two handlers — the pattern scales to every feature you'll ever add.

✅ Checkpoint: both buttons behave. Bonus experiment: reorder the names inside Children and press F5 — the window rearranges. The list is the layout.
9

Try to break it 😈

🔨— ▢ ✕

Professionals sabotage on purpose. After each experiment, Ctrl+Z and confirm F5 still works:

  • 🔡 Change TextBlock to textBlock — instant red squiggle, and the Problems panel reports the type can't be found, with the exact line. Case-sensitivity, Rule 2.
  • ✂️ Delete the semicolon after the Title line — ; expected, again with the line number.
  • 💥 Delete one closing quote from "Say Hello" — suddenly many errors. One missing quote confuses everything after it. Pro ritual: fix the FIRST error first; the rest usually vanish.
  • 🕳️ All fixed? One last test, no code broken: run, leave the box empty, click Say Hello. "Hello, !" — slightly tragic. Nothing crashed, but it isn't smart either. Week 3's if statement fixes exactly this. Remember this moment.
Why celebrate errors?
These are compile-time errors — caught before anything ran, each with a reason and a line number. That's a gift, and it's why we use a compiled language: mistakes surface immediately instead of hiding until the worst moment. Reading errors calmly, top to bottom, first one first, is the most valuable habit you'll build this semester.

Commit vs push — 15-second refresher
Commit = a labeled snapshot 📸 of your code on this machine. Push (inside Sync Changes) = uploading your snapshots to GitHub, where they survive lab-machine amnesia and reach your professor. On a classroom computer, a commit without a push is a photo saved on a camera you're about to hand back.

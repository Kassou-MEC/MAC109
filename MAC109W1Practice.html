1

Install the .NET SDK

🧰

The SDK is the engine that turns your C# into a running program. VS Code is the steering wheel — this is the motor. One-time install, normal Mac style: download, double-click, done.

  1. In Safari or Chrome, go to dotnet.microsoft.com/download.
  2. Click the big Download .NET SDK button. Choose Arm64 (that's for Apple Silicon — any M1, M2, M3, M4 Mac). Only very old Intel Macs need x64.
  3. Open the downloaded .pkg and click Continue until it says installed. All defaults are perfect.
Why do I need this if I already have VS Code?

Kitchen analogy: VS Code is the countertop — a lovely place to work — but the SDK is the oven 🔥. Without it, nothing cooks. The SDK contains the C# compiler (the grammar-checker-translator from the Week 1 deck) and the runtime that executes your program. VS Code just presses its buttons for you.

2

Give VS Code its C# brain

🧠

Fresh VS Code doesn't speak C#. The free C# Dev Kit extension (by Microsoft) teaches it everything: rainbow syntax colors, autocomplete, error squiggles, a Solution Explorer, and — most importantly for us — the ▶ Run button.

  1. Open VS Code. Click the Extensions icon in the left bar (four squares, one flying away) — or press ⇧ ⌘ X.
  2. In the search box, type C# Dev Kit.
  3. Click Install on the top result, published by Microsoft. It automatically brings its friend, the base "C#" extension.
  4. When it finishes, you'll see a new Solution Explorer icon appear — that's your sign it worked.
✅ Checkpoint: Extensions ▸ Installed now lists "C# Dev Kit". High five — setup is done forever. Everything from here is the fun part.
3

Create Lab01 — without typing a single command

✨

Meet the Command Palette — VS Code's magic search box that can do anything. We'll use it to have the SDK build a complete, ready-to-run project for us.

  1. Press ⇧ ⌘ P (Shift + Command + P). A search box drops from the top.
  2. Type new project and choose “.NET: New Project…”.
  3. From the template list, pick Console App.
  4. Name it exactly Lab01_HelloWorld and press Return.
  5. For the location, click Choose folder ▸ go to Documents ▸ click New Folder ▸ name it MAC109 ▸ Select. (All your labs will live here — never in Downloads! 📁)
  6. Press Return to confirm, and when VS Code asks, click Open to open the new project window. If a blue box asks "Do you trust the authors?", click Yes, I trust — the author is you!
What just happened behind the curtain?

The C# Dev Kit asked the SDK to scaffold a Console App — the same thing Visual Studio's File ▸ New ▸ Project does on the Windows lab machines. A console app is a program that talks through text: it prints lines, and it can read what you type. Every concept in Weeks 1–6 lives in console apps; windows and buttons arrive in Week 7.

4

Meet your project

🔎

Look at the Explorer on the left (top icon in the activity bar). The SDK generated a small family of files — here's who's who:

  • Program.cs 💜 — your code. The only file you'll ever edit today.
  • Lab01_HelloWorld.csproj — the project's settings card (like the Project in Visual Studio). Look, don't touch.
  • bin & obj — robot-made folders where compiled results land. Ignore them completely.
Hold on — where are class Program and Main() from the lecture?!

Excellent eye! 👀 Modern C# uses top-level statements: for simple programs, the compiler secretly writes the class Program { static void Main() { … } } wrapper around your code so you don't have to. Both styles are 100% real C#. The classic long form from the Week 1 deck is what truly happens underneath — and we'll write it ourselves when classes arrive in Week 9. For now: less boilerplate, more fun.

5

Press play ▶ — your first execution

🎬

Time to run it. No commands — just the play button.

  1. Make sure Program.cs is open.
  2. Click the ▶ Run button at the top-right of the editor (or press F5 — on a Mac keyboard that's fn F5).
  3. If VS Code asks which debugger, choose C#, then C#: Lab01_HelloWorld. It only asks the first time.
  4. A panel opens at the bottom of VS Code — that's your program's stage. Watch it!
What actually happened when I pressed ▶? (Week 1 flashback)

The whole pipeline from the lecture, in one second: your C# source → the compiler checked every character and translated it to IL → the .NET runtime (JIT) converted IL to machine code for your Mac's chip → the CPU executed it and the text appeared. 🧪 Experiment: delete the semicolon on line 2 and press ▶ again — the compiler refuses and underlines the exact spot in red. That's a syntax error being caught before anything runs. Fix it and feel powerful.

✅ Checkpoint: you saw Hello, World! appear. You just compiled and executed a real program. That's not a small thing — celebrate for 10 seconds. 🎉
6

Write the REAL Lab01 program

✍️

Deliverable #1 needs a banner, a question, your user's name, and a personal goodbye. Select everything in Program.cs (⌘ A), delete it, and type — or paste — this:

Program.cs — Lab01_HelloWorld
// Lab01_HelloWorld — MAC 109
// Author: YOUR NAME — Fall 2026

Console.WriteLine("==============================");
Console.WriteLine("   Welcome to MAC 109!");
Console.WriteLine("   Intro to Visual C#");
Console.WriteLine("==============================");

Console.Write("What is your name? ");
string name = Console.ReadLine();

Console.WriteLine("Nice to meet you, " + name + "!");
Console.WriteLine("See you in class on Friday. Goodbye!");

Save with ⌘ S — the little dot on the file tab turns into an ✕ when saved. Now, what does each piece do?

The // lines — comments

Anything after // is a note for humans; the compiler skips it entirely. Every file you submit starts with your name and the lab number — it's also where you disclose any AI help, per the course policy. 🤖

The four WriteLines — the banner

Each Console.WriteLine("…") prints its text and ends the line, so the four calls stack into a banner. Read one aloud right-to-left: "take this string → hand it to the WriteLine method → which lives inside the Console class." The dot means look inside. 🎁

Console.Write — the one WITHOUT "Line"

Write prints but does not end the line — so the cursor waits right after "What is your name? " and your user answers on the same line. This tiny difference is literally Exercise B2 in your Lab 1 page. 😉

string name = Console.ReadLine(); — your first variable!

Three things happen, right to left: (1) ReadLine() pauses the program and waits for typing + Return. (2) Whatever was typed comes back as a string (text). (3) string name = creates a labeled box 📦 in memory called name and stores the text inside. Variables — boxes with labels — are ALL of Week 2's lecture.

The + in the goodbye line — text glue

With strings, + doesn't do math — it glues text (concatenation): "Nice to meet you, " + name + "!" fuses into one sentence with the real name in the middle. Same symbol, different job depending on the data type. Remember this — it becomes a plot twist in the calculator. 🌀

💡 Feel the IntelliSense: type Console. and pause — a menu of everything inside Console pops up. Arrow down to WriteLine, press Tab. Pros never type full names; they let the editor finish. It also means fewer spelling bugs!

8

Build the calculator

🧮

Second project, same magic: ⇧ ⌘ P → .NET: New Project… → Console App → name it Lab02_Calculator → same MAC109 folder → Open. Then replace Program.cs with:

Program.cs — Lab02_Calculator
// Lab02_Calculator — MAC 109
// Author: YOUR NAME — Fall 2026

Console.WriteLine("=== MAC 109 Calculator ===");

Console.Write("First number: ");
double a = Convert.ToDouble(Console.ReadLine());

Console.Write("Second number: ");
double b = Convert.ToDouble(Console.ReadLine());

Console.WriteLine(a + " + " + b + " = " + (a + b));
Console.WriteLine(a + " - " + b + " = " + (a - b));
Console.WriteLine(a + " * " + b + " = " + (a * b));
Console.WriteLine(a + " / " + b + " = " + (a / b));

Three new ideas 💥

double — a box for decimal numbers

string boxes hold text; double boxes hold numbers that can have decimals (3, 3.5, −41.07). Math needs number boxes. double a and double b give us two. 📦📦

Convert.ToDouble(...) — the crucial transformation

Everything a keyboard produces is text. Type 5, and ReadLine() hands you the string "5" — and here's the trap: "5" + "3" glues into "53"! 😱 Convert.ToDouble transforms text-"5" into number-5.0 so real math can happen. Read the line inside-out: read the text → convert to double → store in box a. (This is quiz question 3 in Lab 1 — now you own it.)

Why the parentheses in (a + b)?

That line mixes both jobs of +: gluing text AND adding numbers. The parentheses force (a + b) to be computed as math first; the answer then gets glued into the sentence. 🧪 Try the sabotage: delete those parentheses, run with 12 and 4, and you'll get 12 + 4 = 124 — everything glued left-to-right as text! Put them back. Breaking things on purpose is genuinely how programmers learn.

Why don't −, ×, ÷ need the same trick?

Because -, *, / mean nothing for text — C# has no choice but to treat them as math. Only + lives a double life.

10

Publish to GitHub — with buttons only

🚀

Your GitHub repo IS your submission. VS Code can create it, upload it, everything — no commands. First, open the whole course folder so both labs travel together: File ▸ Open Folder… ▸ choose Documents ▸ MAC109 ▸ Open.

  1. Click the Source Control icon in the left bar (three connected dots) — or ⌃ ⇧ G.
  2. Click Initialize Repository.
  3. In the Message box, type a real description: Lab 1: HelloWorld and Calculator — then click the big ✓ Commit button. If asked "stage all changes?", click Yes.
  4. Click Publish Branch. VS Code asks you to sign in to GitHub — click Allow and finish in the browser (one time only).
  5. Choose Publish to a PUBLIC repository and name it MAC109-labs.
  6. Done! Click the popup's Open on GitHub — both project folders are online. Copy that page's URL: it's what you paste into Lab 1 and Brightspace. 🔗
What do "commit" and "publish" actually mean?

Commit = take a labeled snapshot 📸 of your code at this moment ("Lab 1 finished"). Publish = upload the snapshots to GitHub, where the world (and your professor) can see them. Later in the course you'll commit after every work session — a time machine for your code.

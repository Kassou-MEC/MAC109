Part 1 · The big idea

A plan, and the things built from it

An architect draws one blueprint for a house. Builders can use it to build many houses. Every house has the same rooms, but each one has its own address, its own paint color and its own family inside.

C# works the same way. You write the plan once. Then you build as many real things from it as you need.

The plan

Class

Describes what every object of this kind has (data) and what it can do (actions). You cannot drive a blueprint of a car.

The real thing

Object

One real item built from the class, living in the computer's memory with its own values. You can build as many as you want from one class.

Part 2 · Definitions

The words you must know

Read each definition, then the real-life version, then the C# line. You will meet every one of these words again in the examples.

Class
A plan (template) that describes a kind of thing: what data it has and what actions it can do. A class is written once, by a programmer.
Real life: the blueprint of a house. The design of a car.
class Car
{
    public string Brand;
}
Object
One real thing built from a class. It lives in the computer's memory and holds its own values. An object is also called an instance of its class.
Real life: your own car, parked outside. It is one instance of the car design.
myCar   // one Car object
Instantiation
The act of building an object from a class. It happens when the keyword new runs. "To instantiate a class" means "to create an object from it".
Real life: the factory building one car from the design.
Car myCar = new Car();
Constructor
A special method inside the class that runs automatically, one time, at the moment an object is built. Its job is to give the new object its starting values. It has the same name as the class and no return type.
Real life: the set-up done at the factory before the car leaves: paint it, put in the seats.
public Car(string brand)
{
    Brand = brand;
}
Field
A variable that belongs to an object. Fields are the object's data: what it has or what it is like.
Real life: a car has a brand, a color, a year.
public string Color;
Method
A block of code that belongs to an object. Methods are the object's actions: what it can do.
Real life: a car can start, stop and honk.
public void Honk()
{
    Console.WriteLine("Beep!");
}
The new keyword
The word that builds an object. Each time new runs, one more object exists in memory.
Real life: pressing the "build" button at the factory.
new Car()
The dot .
Means "go inside this object". Use it to reach an object's fields and methods.
Real life: "my car's color", "my car, honk!"
myCar.Color = "Red";
myCar.Honk();
public and private
public members can be used by any code. private members can be used only by code inside the same class.
Real life: the steering wheel is public. The engine's inside is private.
public string Owner;
private double balance;
Reference
What an object variable really holds: not the object itself, but a link to it. Two variables can link to the same object.
Real life: a remote control is not the TV. Two remotes can control one TV.
Car sameCar = myCar;

Part 6 · From the console to your GUI

Your window is made of objects

Everything you just practiced is exactly how a GUI is built. A Window, a Button, a TextBlock and a TextBox are all classes. The Avalonia team already wrote those plans for you. Your job is to instantiate them with new, set their data, and put them in the window.

Two buttons on the screen are two objects built from the one Button class, the same way Rex and Bella are two objects built from the one Dog class.

The two GUI examples go in MainWindow.cs of your Avalonia project. Program.cs stays exactly as it is. In a GUI, an object's data is called a property (Title, Text, Content). You use a property just like a field: with the dot.

Part 7 · Watch out

Four mistakes everyone makes once

Forgetting new

Car myCar;
myCar.Brand = "Toyota";   // error
Car myCar = new Car();
myCar.Brand = "Toyota";   // works

Without new there is a name but no car. You have a key ring with no car attached to it.

Using the plan instead of the thing

Car.Brand = "Toyota";     // error
myCar.Brand = "Toyota";   // works

Car is the blueprint. A blueprint has no brand. Only a real car object, like myCar, has one.

Forgetting public

class Car { string Brand; }
myCar.Brand = "Toyota";   // error
class Car { public string Brand; }

Without public, a field is private. Code outside the class, like Main, is not allowed to touch it.

Building a control but never adding it

Button okButton = new Button();
okButton.Content = "OK";  // invisible
panel.Children.Add(okButton);

The button object exists in memory, but nobody put it in the window. A sofa still in the delivery truck is not in your living room.
